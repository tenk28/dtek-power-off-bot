# Бот графіків відключень ДТЕК

Telegram-бот, який кожні 5 хвилин перевіряє графік відключень **ДТЕК Київські регіональні електромережі**
для однієї черги (за замовчуванням **3.2**) і публікує в канал картинку графіка разом з інтервалами
відключень на сьогодні.

- Новий пост з'являється раз на день, коли виходить графік на сьогодні, і щоразу, коли графік на сьогодні змінюється.
- Якщо дані не вдається отримати 3 перевірки поспіль, бот пише попередження в окремий чат адміністратора.
  Коли дані знову надходять, він повідомляє про відновлення.
- Написано на Rust. Образ Docker важить ~2 МБ, бот запускається на Raspberry Pi 5, деплой робиться однією командою з ноутбука.

Приклад посту:

```
⚡ Графік відключень на сьогодні
📅 Субота, 24 жовтня
🏠 Черга 3.2 · Київська обл.

🔴 08:00–12:00 — світла немає

Без світла сьогодні: 4 год
🕒 Оновлено ДТЕК: 24.10.2026 14:42
```

## Звідки дані

Сайт ДТЕК захищений капчею, тому бот його не парсить. Дані беруться з публічного дзеркала
[Baskerville42/outage-data-ua](https://github.com/Baskerville42/outage-data-ua): воно кожні ~5 хв забирає
графіки з сайтів ДТЕК і публікує їх як JSON і PNG. Через кеш GitHub і саме дзеркало пост з'являється
з затримкою до ~10–15 хв після оновлення на сайті ДТЕК.

## 1. Створення бота в BotFather

1. Відкрийте [@BotFather](https://t.me/BotFather) і надішліть `/newbot`.
2. Задайте ім'я та username бота, наприклад `my_dtek_schedule_bot`.
3. BotFather надішле токен вигляду `1234567890:AA...`. Збережіть його: він знадобиться для `.env`.
   Токен — це пароль від бота. Не публікуйте його і не комітьте в git.

## 2. Додавання бота в канал

1. Створіть публічний канал або відкрийте наявний.
2. Відкрийте **Налаштування каналу → Адміністратори → Додати адміністратора**, знайдіть свого бота за username.
3. Залиште боту право **«Публікувати повідомлення»**, решта прав не потрібна.
4. `channel_id` — це `@username` каналу. Для приватного каналу використовується числовий id вигляду `-100…`,
   його можна дізнатися, переславши повідомлення з каналу боту [@userinfobot](https://t.me/userinfobot).

Чат для попереджень про збої (`alert_chat_id`):

1. Напишіть своєму боту будь-яке повідомлення (`/start`), інакше він не зможе писати вам першим.
2. Дізнайтеся свій числовий id, наприклад через [@userinfobot](https://t.me/userinfobot).
3. Укажіть цей id як `alert_chat_id`. Підійде й група, куди доданий бот (її id від'ємний).
   Якщо `alert_chat_id` не задано, попередження йдуть у канал.

## 3. Налаштування

```bash
cp config.example.toml config.toml
cp .env.example .env
```

У `.env` вставте токен:

```
TELEGRAM_BOT_TOKEN=1234567890:AA...
```

У `config.toml` укажіть щонайменше `channel_id`, `alert_chat_id` і `queue`:

| Параметр | За замовчуванням | Що означає |
|---|---|---|
| `telegram.channel_id` | — | канал для постів (`@username` або `-100…`) |
| `telegram.alert_chat_id` | `channel_id` | куди писати попередження про збої |
| `telegram.silent` | `false` | надсилати пости без звуку |
| `schedule.region` | — | `kyiv-region` (також є `kyiv`, `dnipro`, `odesa`) |
| `schedule.queue` | — | черга, напр. `3.2` |
| `schedule.region_title` | з даних | назва регіону в пості |
| `polling.check_interval_secs` | `300` | як часто перевіряти (≥ 60) |
| `polling.failure_alert_threshold` | `3` | скільки невдалих перевірок поспіль до попередження |
| `polling.stale_after_secs` | `10800` | дані, старші за цей час, вважаються застарілими |
| `polling.image_wait_max_secs` | `900` | скільки чекати оновленої картинки після зміни графіка |
| `polling.missing_today_grace_secs` | `3600` | скільки після опівночі не вважати збоєм відсутність графіка на новий день |
| `storage.state_path` | `/data/state.json` | файл стану (у Docker — том `./data`) |

Невідомі або помилково написані параметри бот не ігнорує: він зупиняється на старті з поясненням у лозі.

## 4. Деплой на Raspberry Pi однією командою

Що потрібно один раз підготувати:

- **На ноутбуці** (Linux x86_64): Docker з `buildx` і [`just`](https://github.com/casey/just)
  (`cargo install just` або `sudo apt install just`). QEMU не потрібен: збірка під arm64 — це крос-компіляція.
- **На Pi** (64-бітна Raspberry Pi OS): Docker з плагіном compose і SSH-доступ за ключем.

  ```bash
  curl -fsSL https://get.docker.com | sh
  sudo usermod -aG docker $USER   # потім перелогіньтесь
  ```

  Ключ з ноутбука: `ssh-copy-id pi@raspberrypi.local`.

Деплой:

```bash
just deploy
```

Команда збирає образ під arm64, копіює на Pi образ, `docker-compose.yml`, `config.toml` і `.env`,
після чого (пере)запускає контейнер. Стан зберігається в `~/dtek-bot/data` на Pi, тож перезапуск
не публікує повторно той самий графік. Після зміни `config.toml` або `.env` достатньо знову виконати `just deploy`.

Інший хост чи директорія на Pi:

```bash
PI_HOST=pi@192.168.1.50 PI_DIR=~/bots/dtek just deploy
```

Контейнер працює від користувача з UID 1000 (на Pi це зазвичай перший користувач). Якщо ваш користувач
має інший UID, змініть `user:` у `docker-compose.yml` або виконайте на Pi `sudo chown 1000:1000 ~/dtek-bot/data`.

## 5. Логи і стан

```bash
just logs     # стежити за логами на Pi
just status   # стан контейнера
```

На кожну перевірку в лозі з'являється один рядок, наприклад `result=unchanged`, `result=posted (daily)`,
`result=waiting for image` або `result=failed: ...`. Детальніший лог вмикається через `RUST_LOG=debug` у `.env`.

## Розробка

```bash
just test         # cargo fmt --check, clippy -D warnings, тести
just run          # локальний запуск з config.toml і .env (стан у ./data)
just build-local  # образ amd64 для запуску на ноутбуці
```

Для перевірки зручно створити тестовий канал і вказати його в `config.toml`.

Тести не ходять у мережу: вони працюють на реальному знімку даних `tests/fixtures/kyiv-region.json`
і на локальних мок-серверах замість дзеркала та Telegram.

### Як бот вирішує, чи публікувати

- Графік на сьогодні ще не публікувався (новий день або перший запуск) — пост «⚡ Графік відключень на сьогодні».
- Години відключень на сьогодні змінилися — пост «🔄 Графік на сьогодні оновлено».
- Змінився лише час «Оновлено ДТЕК», а години ті самі — нового посту немає.
- JSON і картинка кешуються окремо, тому картинка може відставати від JSON. Якщо графік змінився,
  а картинка ще стара, бот чекає її оновлення до 15 хв, а потім публікує з наявною.
